# 依頼：昭和のリビングで遊ぶピンポン野球を実装してください

このZIP内の画像を使い、iPad横持ちを中心に、1台を交互に渡して2人対戦するWebゲームを作ってください。ユーザーはPCを持っていません。実装・画像配置・ビルド・必要な修正はあなたが担当し、ユーザーにBlenderやPCでの加工を求めないでください。外部AI API、課金API、バックエンド、会員登録は不要。静的ホスティング可能にしてください。自動公開はせず、まず動くプレビューと検証結果を出してください。

## 目的と見た目
子供のころ、新聞紙を丸めたバットとピンポン玉で家の中で野球をした遊び。魔球を作る楽しさ、相手の球を見極める楽しさ、家具を避けて打つ緊張感を重視します。reference/visual_target.pngが見た目の目標です。UIを含む参考画像を背景に使わないこと。実背景はassets/background/living_room.png。人物は個別透過PNGを使い、棒人間や単純な立体に置き換えないでください。

固定打者カメラの2.5D構成を採用。描画は2Dでも球の位置と衝突は奥行きのある論理座標で管理します。背景に合う透視投影を共有し、ミートカーソル・球・衝突位置がずれないようにする。画像だけで任意方向からのカメラ映像は作れないため、自由カメラは実装しません。打球追跡は同じ画面内の球の軌跡で表現。参考画像との比較をしながら人物サイズと位置を調整してください。

## 確定ルール（特に重要）
打球がセーフになる場所は次の4か所だけです。
1. 奥の左右のカーテンとカーテンの間。
2. 右のドア。
3. カレンダー付近。
4. 左奥のタンスの上。
これ以外はすべてアウトです。ソファ・クッション・床・テレビ・電球・カーテンそのものもアウト。以前の「クッションや洗濯かごなら安全」という案は採用しないでください。
投手の守備範囲への返球もアウト。背景上はセーフ区域と重なっていても、先に投手の守備範囲に入ったらアウトです。打球が最初に衝突した面で1回だけ結果を確定し、その後の跳ね返りで結果を変えない。
zones.initial.jsonの座標は背景画像を見た初期推定です。reference/safe_zones_preview.jpgの緑色1〜4が対応します。これは確定した精密境界ではありません。特に「右のドア」は画面右端の引き戸を仮指定しています。隣の細いガラス戸との解釈差を直せるよう編集可能にしてください。

三振は1アウト、1アウトで攻守交代。見送り時は打者前の判定面を通過した球の位置でストライク／ボールを判定。空振りはコースによらずストライク。4ボールで出塁し攻撃続行。投球が家具・床などに先に当たる、または打者の判定面に到達しない場合は1ボール（打者のアウトではない）。1投球につき結果は1回だけ。
簡易得点ルール：ヒットと四球は打者が一塁に入り、既存走者も全員1塁進む。ホーム到達で1点。アウト時は走者とボール・ストライクをリセットして交代。ヒット／四球後もカウントはリセット。標準3回、各回双方1アウトずつ攻撃し、最終回も両者の攻撃を完了して比較。同点は引き分け。通常野球の押し出しルールとは異なる簡易ルールであることを遊び方に短く記載。

## 1台での投球・打撃
状態を明示的に分離：投球編集→投手プレビュー→設定確定→端末受け渡し→打者準備→投球→打撃／見送り→結果→次の投球または交代。
投球確定後は軌道や球速の設定を完全に隠す。受け渡し中に投球しない。打者の準備OK後に短いカウントダウン。打者画面に投球軌道の予告線や終点を表示しない。

### 投手
球速をスライダーで指定。道筋は指で自由に設定し、初期版は上からの左右曲がりと横からの上下変化を同じ奥行きに対して編集。横軸を投手→打者の進行度に統一し、同じ深さで左右と高さを合成する。数点の制御点を指で動かせる操作とフリーハンド入力を用意。補間は暴走しない方式にし、始点はリリース位置に固定、奥行きは単調前進、途中で逆走・無限ループは不可。曲がり・速さ・加速度に上限を設定し、打者が反応できない瞬間移動を防ぐ。球速は投球全体の所要時間に変換、プレビューと本番は同一計算結果を使う。終点はゾーン外も設定可能で、ボール球を振らせる駆け引きを許す。リセットと試し投げを用意。

### 打者
打者背後のカメラ。左手でミートカーソル、右手の大きい「打つ」ボタン。マルチタッチ対応、指のIDを分離し、カーソル操作とスイングが干渉しない。画面スクロールやズームとの競合を抑える。ボタン押下→短い一定の振り出し時間→インパクトの時刻を明確にし、その時刻付近だけ当たり判定する。ボタン連打で何回も打てない。
球とカーソルの距離だけでなく、奥行きが打撃可能範囲か確認。球は手前ほど大きくし床影と短い残像で距離を示す。ピンポン玉は縫い目なし。打球方向は早い／遅いタイミングと芯の上下左右ずれで連続的に変化、狙った方向へ打てるようチューニングする。命中後の進路をランダム抽選にしない。常に強打が有利にならない設計。

## セーフ範囲編集と衝突
背景の画像座標(0〜1)を基準に4区域のポリゴンを保持。判定用の壁面・目標面と投影の対応を定義し、球がまだ手前にあるのに画面上で区域に重なっただけでヒットにしない。球と障害物はフレーム間の移動線分も判定し、速い球のすり抜けを防ぐ。最も早い衝突を採用。安全区域の縁は内側をセーフとする等、一貫した境界規則にする。投手の守備範囲、電球、テレビなど手前の障害物を優先して遮蔽できること。
設定画面に「判定範囲を調整」を作り、背景上で4つの緑ポリゴン、投手守備範囲、電球の判定を表示。頂点を指で移動・保存・初期化・JSON書き出し／読み込み可能にする。公開プレイでは非表示、練習ではセーフ区域を薄く表示できる。判定と描画は同じ座標変換を使用し、画面サイズ変更や余白でもずれない。

## 素材の使い方
assets/pitcher/pitcher_01.png〜12.png：12コマ。08をリリースの仮基準にし、手から球が出るよう表示位置を調整。
assets/batter/batter_01.png〜12.png：最新修正版。05・06は頭の後ろにバットを引く。07〜08がインパクトの仮基準。06→07は変化が大きいため再生時間を調整して確認する。人物に描き込まれたバットと別バットを二重表示しない。
人物画像は480×440の共通キャンバス、足元基準はmanifest参照。元絵にコマごとの姿勢や縮尺差が残るため、個別の表示補正を設定で持つ。足元をそろえたがアニメーション品質を検証済みとは扱わない。中割り画像が必要ならどのコマ間か報告する。画像のクロスフェードを乱用して二重の腕やバットにしない。
小物はassets/props/の個別透過PNG。lamp_intact/lamp_brokenは背景上部に配置し破損時差し替え。二枚の絵の余白が異なるので、コードの共通アンカーで位置・大きさを合わせる。花瓶も同様。glass_fragmentsは破片の集合画像。透明画像を黒背景として扱わない。
バット折れは追加演出として素材を同梱。初期対戦では公平性のためランダムな折れで結果を変えず、基本の投球打撃完成後に実装。人物画像内のバットの置換が未解決なら折れ演出を無理に追加しない。
ソファ・テレビ等は背景に焼き込まれた絵。独立して移動や破壊できる素材はない。テレビ等に当たったときは揺れ・短い音・アウト表示で表現。電球はパリン→短い間→「こらー！」の文字演出。声素材は含まれないので音声ファイルがあるように扱わない。効果音はWeb Audioで短く合成しミュート可能、初回タップで有効化。

## 実装順と検証
1. 素材読み込み、背景・人物・電球の配置を完成見本と比較。透過周辺の色にじみや番号の残りを確認。
2. 単純な直球で打撃の操作と衝突を完成。
3. 軌道編集、受け渡し、ボール／ストライク、走者と交代を追加。
4. 4つのセーフ領域・それ以外のアウト・調整画面を仕上げる。
5. 魔球と音、破損演出、iPad向け仕上げ。
有効な画像を使う前に見た目を単純図形へ置き換えない。詰まったときも仕様を無断で別ゲームにしない。
必須確認：4ボールで交代しない／3ストライクで交代／ヒット後カウントリセット／4セーフ領域それぞれヒット／それ以外と投手はアウト／電球が先なら奥がセーフでもアウト／見送り球の判定／投球中リサイズ／連打で二重加点なし／受け渡しで設定が見えない／高速球のすり抜けなし／マルチタッチ／再戦で全状態初期化。ロジックはテストし、見た目はスクリーンショットと連続再生で確認。実機未確認ならそう明示し、実行コマンド・検証結果・残る調整箇所を最後に簡潔に報告してください。
