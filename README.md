# リビング・ピンポン野球

昭和のリビングで、新聞紙バットとピンポン玉で遊ぶ野球ゲームです。
iPad 横持ちで、1台を交互に渡して2人で対戦します。静的ファイルだけで動きます（サーバー処理・外部API・会員登録なし）。

- 仕様: [docs/SPEC.md](docs/SPEC.md)（キット同梱の依頼書）
- 素材: `assets/`（キットの画像そのまま）、判定範囲の初期値: `zones.initial.json`
- 見た目の目標: `reference/visual_target.png`（背景としては使っていません）

## 動かし方

ビルドは不要です。フォルダをそのまま静的ホスティングに置けば動きます。

```sh
npm run serve        # = python3 -m http.server 8080 → http://localhost:8080/
npm test             # ロジックのテスト（node --test）
node tools/verify.mjs [出力先]       # ブラウザでの動作確認（Playwright/Chromium、サーバー起動中に）
node tools/screenshots.mjs [出力先]  # 画面の連続スクリーンショット
```

## 遊び方（ゲーム内「遊び方」と同じ）

- **セーフ（ヒット）は4か所だけ**: ①奥のカーテンとカーテンの間 ②右のドア〜右の壁（天井まで・右奥まで） ③カレンダー付近 ④テレビの上〜左奥の壁。
  それ以外（床・ソファ・テレビ・写真立て・カーテン・電球など）はすべてアウト。投手の守備範囲に先に入ってもアウト。
- 見送り: 打者の前の枠（判定面）を通ればストライク、外ればボール。空振りはコースによらずストライク。
- 投球が床や電球に先に当たったら1ボール（打者のアウトではない）。
- 3ストライクで1アウト、**1アウトで攻守交代**。4ボールで出塁して攻撃続行。
- **簡易ルール**: ヒットも四球も、打者が一塁へ入り既存の走者は全員1つ進みます（通常野球の押し出しとは違います）。ホームに帰ると1点。
  ヒット・四球のあとカウントはリセット。アウトで走者とカウントをリセットして交代。
- 標準3回（設定で1・3・5回）。最終回も両者が攻撃してから比べます。同点は引き分け。

### 1台での流れ

投球編集 → 端末受け渡し（不透明な画面） → 打者準備（カーソル練習・準備OK） → 3・2・1 → 投球 → 打撃／見送り → 結果 → 次の投球、または攻守交代。

- **投手**: 球速スライダー、「上から見た曲がり」と「横から見た高さ」を同じ横軸（投手→打者の進行度）で編集。
  点を動かす／指でなぞるの2方式。球速はバーのどこを触っても、なぞった位置の値になります。始点はリリース位置に固定、奥行きは常に前進。曲がり・速さには上限があり、範囲外は自動で抑えます。
  終点はゾーン外もOK。「試し投げ」は本番と同じ計算です。確定後は設定・予告線は一切表示しません。
- **打者**: 左手で画面左側をドラッグしてミートカーソル、右手の「打つ」。マルチタッチ対応（指ごとに分離）。
  押してから一定時間（0.16秒）後がインパクトで、その瞬間の球の奥行きとカーソルからのずれだけで当たりを判定。1投球1回だけ。
  早く振る（球がまだ奥）と左へ、遅いと右へ。芯より球が上なら打ち上がり、下ならゴロ。乱数は使いません。

PC で確認するときは矢印キー（またはWASD）でカーソル、スペースで「打つ」。

## 判定範囲の調整

タイトル → 設定 → 「判定範囲を調整」。背景の上に、セーフ4区域（緑）・投手守備範囲（赤）・電球（橙）・テレビ／花瓶（灰）が出ます。
頂点や楕円の点を指で動かし「保存」（端末内に保存）。「初期化」で `zones.initial.json` に戻ります。「JSON書き出し／読み込み」もできます。
練習モードでは設定によりセーフ区域を薄く表示します（対戦中は非表示）。

JSON には画像上の形（0〜1の正規化座標）と、その形がある「面」を持たせています。

| 項目 | 面（ワールド座標） |
| --- | --- |
| カーテンの間・カレンダー付近 | 奥の壁 `z = 5.2` |
| 右のドア〜右の壁 | 右の壁 `x = 1.99` |
| テレビの上〜左奥の壁 | 奥行き `z = 3.0` の面（左の壁より内側に収まる奥行き） |
| 投手守備範囲 | `z = 4.4`（投手の足元の奥行き） |
| 電球 | `z = 3.2` |
| テレビ / 写真立て / 花瓶（アウト） | `z = 3.6` / `z = 2.95` / `z = 2.87` |

## しくみ（2.5D）

- 背景に合わせた固定カメラ（`src/config.js` の `CAMERA`）で、ワールド座標（m相当）⇔ 背景画像座標 ⇔ 画面座標を `src/projection.js` で変換。描画と判定は同じ変換を使い、画面は contain（余白付き）で収めるのでリサイズや余白でもずれません。
- 打球はサブステップ（1/240秒）ごとの**移動線分**と各面の交差を求め、**最も早い衝突**で結果を1回だけ確定（`src/physics.js`）。同時刻なら投手・電球・障害物を優先。その後の跳ね返りは見た目だけ。
  球がまだ手前にあるのに画面上で区域に重なっただけではヒットになりません。区域の縁はセーフ側（内側）。
- 投球軌道は5つの制御点を単調3次補間（PCHIP、行き過ぎなし）でつなぎます（`src/pitch.js`）。
- ルールは純粋関数（`src/rules.js`）、1投球の進行と判定は `src/pitchRun.js`。

## 残っている調整箇所

- 判定範囲は初期推定のままです。特に「カレンダー付近」の初期値は壁掛け電話の周りにあり、実際のカレンダー（右のドア横）とは位置がずれています。「右のドア」も右端の引き戸を仮指定しています。調整画面で直してください。
- 打者の大きさ・位置は固定で、構え（01）の頭とバットが投手に重ならないよう完成見本より小さめ（`SPRITES.batter`）。動くのはミートカーソルだけです。
- 打者 06→07 の変化が大きいため 06・07 の表示時間を短くしています（`BATTER_ANIM`）。滑らかさが足りなければ **06と07の間** の中割り画像が1枚あると改善します。投手は 07→08（リリース）間も動きが大きめです。
- 人物画像の縁の暗いにじみは読み込み時に半透明部分を弱めて軽減していますが、元絵の輪郭線は残ります。投手 07・08 の足元に小さな欠け・汚れがあります。
- 打球の飛び方（`SWING`・`PHYSICS`）は数値シミュレーションで調整済みですが、実際に遊んでの手触り調整が必要です。
- バット折れ（`bat_bent.png`）は人物画像にバットが描き込まれていて置き換えられないため未実装です。`glass_intact.png` も未使用です。
- 効果音は Web Audio の簡易合成です（声素材はなし。「こらー！」は文字演出）。
